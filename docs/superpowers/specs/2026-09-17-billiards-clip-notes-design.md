# 당구 캡처 메모 — 설계

날짜: 2026-09-17  
상태: 승인 대기

## 한 줄 요약

폰으로 당구 영상을 보다가 화면을 캡처하고, 사진 아래에 공부 메모를 적는다. 목록은 시간순이다. 태그는 사용자가 달지 않는다. 여러 메모에 반복된 단어만 앱이 분류 버튼으로 만든다.

## 목표와 성공 기준

- 유튜브 등에서 캡처한 뒤, 이 앱에서 사진 선택 → 한두 줄 메모 → 저장까지 짧게 끝난다.
- 홈 화면에 추가해 두고 폰에서 앱처럼 연다.
- 같은 단어가 서로 다른 메모에 두 번 이상 나오면, 목록 위에 그 단어 버튼이 생긴다.
- 로그인, 서버, Firebase, 다른 기기 동기화는 없다. 기록은 그 폰의 브라우저 저장소에만 남는다.

## 사용자와 핵심 흐름

사용자: 폰으로 당구 영상을 보며 장면마다 이유를 남기고 싶은 사람.

1. 영상에서 화면 캡처
2. 이 앱을 연다 (홈 화면 아이콘 또는 브라우저)
3. `+` → 갤러리에서 방금 캡처 선택
4. 사진 아래 메모 칸에 적는다 (비워 두고 저장해도 된다)
5. 저장하면 기록 목록 맨 위에 보인다
6. 나중에 같은 단어가 반복되면 그 단어 버튼으로 모아 본다

## 화면

화면은 두 개다.

### 기록 목록

- 기본 정렬: 최신순 (`createdAt` 내림차순)
- 각 행: 썸네일 + 메모 앞부분(최대 2줄). 메모가 비어 있으면 “메모 없음”
- 상단 `+` 버튼으로 새 기록
- 행을 누르면 해당 기록 편집 화면
- 상단 분류 줄: 조건을 만족하는 단어만 버튼으로 표시. 해당 단어가 하나도 없으면 분류 줄 자체를 그리지 않는다. 오류 메시지는 없다
- 단어 버튼을 누르면 그 단어가 들어 있는 기록만 최신순으로 남긴다. 같은 버튼을 다시 누르면 전체 목록으로 돌아간다. 동시에 켜지는 단어는 하나뿐이다

### 새 기록 / 편집

- 위: 사진 (새 기록은 갤러리에서 고른 캡처, 편집 시에는 기존 사진)
- 아래: 여러 줄 메모 칸. 줄노트처럼 보이면 된다
- 새 기록: 사진은 필수, 메모는 선택
- 편집: 사진 교체는 없다. 메모만 수정한다
- 저장, 뒤로(목록으로)
- 편집 화면에만 삭제. 확인 한 번 후에 그 기록과 사진을 지운다

## 자동 분류

사용자가 태그를 고르거나 고치지 않는다. 합치기, 이름 바꾸기, 숨기기는 넣지 않는다.

저장·수정할 때마다 그 메모 글에서 단어 집합을 뽑아 기록에 저장한다. 목록을 그릴 때 모든 기록의 단어 집합을 모아, **서로 다른 기록에 2회 이상** 등장한 단어만 버튼이 된다. 한 메모 안에서 같은 단어가 여러 번 나와도 그 기록에서는 1회로 센다.

### 단어 추출

1. 메모를 공백·줄바꿈·문장부호 기준으로 나눈다
2. 각 조각 앞뒤에서 흔한 조사만 뗀다: `은, 는, 이, 가, 을, 를, 의, 에, 에서, 으로, 로, 와, 과, 도, 만, 부터, 까지, 한테, 께`
3. 한글·영문·숫자만 남긴다. 영문은 소문자로 맞춘다
4. 한 글자 단어는 버린다
5. 불용어는 버린다: `그리고, 그래서, 근데, 그러나, 너무, 아주, 조금, 그냥, 정말, 진짜, 이거, 저거, 그것, 이것, 오늘, 지금, 하다, 있다, 없다, 같다, 되다, 이다, 않다`
6. 남은 것을 그 기록의 단어 집합으로 둔다

예: “짧게 끌어치기”, “끌어치기 각이 큼”, “배치만 보고 쳤음” → 버튼은 `끌어치기`만. `배치`는 기록이 하나뿐이면 아직 안 뜬다.

필터는 폴더가 아니다. 선택한 단어가 단어 집합에 들어 있는 기록만 보여 준다. 한 기록은 여러 단어 버튼에 걸릴 수 있다.

## 데이터와 저장

서버 없음. 인증 없음. Firebase 없음.

브라우저 IndexedDB에만 저장한다. DB 이름 `billiards-notes`, 저장소 `entries`.

한 기록:

| 필드 | 의미 |
| --- | --- |
| `id` | 문자열 UUID |
| `createdAt` | 생성 시각 (밀리초) |
| `updatedAt` | 마지막 메모 수정 시각 (밀리초) |
| `image` | 축소한 사진 Blob |
| `memo` | 문자열. 빈 문자열 허용 |
| `keywords` | 추출된 단어 문자열 배열 (중복 없음) |

사진은 넣을 때 긴 변 1280px 이하, JPEG 품질 0.8로 줄인 뒤 Blob으로 저장한다. 원본 파일은 보관하지 않는다.

같은 폰, 같은 브라우저에서만 유지된다. 앱 데이터·사이트 데이터를 지우면 기록도 사라진다. 다른 폰과 맞춰 주지 않는다.

PWA로 홈 화면에 추가할 수 있다. 이미 저장된 목록·사진은 오프라인에서도 연다. 새 사진은 기기 갤러리에서 고른다.

## 기술 선택

- Vite + TypeScript + React
- 라우팅은 목록(`/`)과 편집(`/new`, `/entry/:id`) 정도
- IndexedDB는 `idb` 사용
- PWA는 `vite-plugin-pwa`
- 단위 테스트는 Vitest
- UI는 폰 너비 우선. 큰 화면에서도 가운데 좁은 폭으로 보이게 한다

## 오류와 빈 상태

- 사진 없이 새 기록 저장: 저장하지 않고 “캡처를 먼저 고르세요”
- 갤러리 접근 실패: “설정에서 사진 접근을 허용하세요”
- 이미지 축소 실패: 저장하지 않고 “다른 캡처를 고르세요”
- IndexedDB 할당량 초과: “저장 공간이 부족합니다. 이 앱 데이터를 비우거나 기록을 지우세요”
- 메모만 비어 있음: 저장 허용
- 분류 단어 없음: 분류 줄을 그리지 않는다. 에러 메시지 없음
- 없는 `id`로 편집 URL: 목록으로 돌리고 “기록을 찾을 수 없습니다”
- 삭제는 confirm 한 번. 취소하면 그대로 둔다

## 테스트

자동 (Vitest):

- 조사·불용어를 빼고 단어를 뽑는다
- 한 글자 단어는 분류 후보가 아니다
- 서로 다른 기록에 2회 이상인 단어만 버튼 목록에 오른다
- 한 기록 안 중복은 1회로 센다
- 목록은 `createdAt` 내림차순이다
- 사진 없는 새 기록은 저장 로직이 거절한다
- 단어 필터는 해당 `keywords`를 가진 기록만 남긴다

수동 (폰 브라우저):

- 캡처 선택 → 메모 → 저장 → 목록 최상단에 보임
- 같은 단어로 두 기록을 저장하면 버튼이 생김
- 버튼 on/off로 필터가 맞고, 전체로 돌아옴
- 메모 수정 후 단어 버튼이 바뀜 (조건을 잃으면 버튼이 사라짐)
- 삭제 확인 후 목록에서 사라짐
- 홈 화면 추가 후 비행기 모드에서도 기존 기록이 열림

## 이번 버전에 넣지 않는 것

- Firebase, 로그인, 클라우드 동기화
- 사진 위에 그리기, 화살표, 크롭
- 사진 교체
- 분류 단어 수동 추가·병합·삭제
- 검색창, 폴더, 여러 단어 동시 필터
- 영상 구간 저장, 유튜브 링크 연동
- 공유하기 시트로 앱 열기
- 다계정, PC 전용 레이아웃

## 구성 단위

- `wordExtract`: 메모 문자열 → 단어 집합. UI·저장에 의존하지 않음
- `classify`: 기록 배열 → 2회 이상 단어 목록
- `db`: 기록 CRUD + 이미지 Blob
- `imageResize`: File → JPEG Blob
- `ListPage`, `EditorPage`: 화면만 담당
